# AB#1683083

## Executive Summary

Each brand theme's stylesheet used to load its fonts from one fixed web address per font, so a new font version could not be tried in the test or QA environments without changing what guests see in production. This change adds separate test and QA versions of every brand theme stylesheet (Alaska, Alaska Classic, Atmos and Hawaiian). Each version loads its own copy of every font — English, Japanese and Korean — from a permanent address whose file name ends in "-test" or "-qa". Production stylesheets are unchanged. An automated check runs on every pull request and confirms the test and QA versions are identical to production except for which font files they load, so what is tested is what ships.

Tracking ticket: [AB#1683083](https://itsals.visualstudio.com/E_Retain_Content/_workitems/edit/1683083).

## The Problem

Teams want to try a new version of a brand font in test and QA before guests ever see it. Every theme stylesheet pointed at a single copy of each font file, and all environments loaded that same copy. Trying a new font anywhere meant replacing it everywhere, including production. There was also no way to prove that a test or QA stylesheet matched production in everything but the font, so an environment-specific build could drift without anyone noticing.

## Root Cause

Font URLs were fixed at build time with no notion of environment, and the build produced one stylesheet per theme:

- The `font-face` mixin ([_fontFace.scss](../../src/utilityMixins/_fontFace.scss)) emitted `url("#{$i18n-font-base-path-en}/#{$filename}.woff2")`, with no input that could vary the file name per environment.
- The `font-face-i18n` mixin ([_fontFaceI18n.scss](../../src/utilityMixins/_fontFaceI18n.scss)) emitted `url("#{$path}.woff2")` for the Japanese and Korean Noto Sans fonts, with the same limitation.
- The theme build ([theme.global.css.build.mjs](../../scripts/theme.global.css.build.mjs) and [theme.global.css.config.mjs](../../scripts/theme.global.css.config.mjs)) compiled [theme.global.template.scss](../../src/bundled/themes/theme.global.template.scss) once per theme into `dist/bundled/themes/<theme>.global(.min).css`. There was only one output per theme, so there was nowhere to put an environment-specific build.

## The Fix

- **Environment setting and shared suffix function** ([_fontUtils.scss](../../src/utilityVariables/_fontUtils.scss)): added `$font-env: null !default`, the allowed list `$font-envs: ("test", "qa")`, and `font-env-suffix($env)`. The function returns `''` for `null`, `-test`/`-qa` for a supported value, and `@error`s for anything else.
- **Mixins:** `font-face` and `font-face-i18n` gained an optional `$env` argument that defaults to `fontUtils.$font-env`. Both insert `font-env-suffix($env)` before `.woff2`, for example `ASCircularWeb-Light-test.woff2` and `noto-sans-jp-v54-japanese-300-qa.woff2`.
- **Template:** the theme template now starts with `@use "../../utilityVariables/fontUtils" with ($font-env: FONT_ENV);`. The build replaces the `FONT_ENV` placeholder with `null`, `"test"` or `"qa"`.
- **Build:** the config builds every standard theme for each of `[null, 'test', 'qa']`. Production is written to `themes/<theme>.global.css` and the environments to `themes/<theme>-<env>.global.css`, each with a `.min.css` twin. That's 16 new files across the four themes.
- **Tests:**
  - [fontFace.spec.scss](../../tests/fontFace.spec.scss) is a Sass True spec covering the default, `test` and `qa` output of both mixins.
  - [themeFontEnvironments.spec.js](../../tests/themeFontEnvironments.spec.js) is a post-build Jest spec. For every production stylesheet (expanded and minified), it removes the `-<env>` suffix from each font URL in the matching test/QA file and asserts the result is byte-identical to production. It also checks that production has no suffixed URLs, that every English/Japanese/Korean URL in an environment file is suffixed, and that `dist/bundled/themes/` holds only production files and their `-test`/`-qa` versions. The spec also checks that the `$font-env` setting reaches both mixins and that invalid values are rejected.
- **CI:** the build action now runs `npm ls --omit=dev --all` to verify the production dependency tree.
- **Docs:** README ("Test and QA font environments") and MIGRATION.md (a non-breaking v12.x section).

## Why This Works

- **Production can't change by accident.** The default is `null`, which produces an empty suffix, so the production URLs and files are byte-identical to before. CI's "committed build output is up to date" check confirmed no production file under `dist/` changed. Existing consumers who don't pass `$env` or set `$font-env` see no difference.
- **One source of truth.** Both mixins call the same `font-env-suffix()` function, so English and Japanese/Korean fonts can't diverge in naming or validation. A typo such as `$env: staging` is a compile error rather than a silently broken URL.
- **Builds can't silently drift.** The environment stylesheets are compiled from the same template as production, with only the Sass setting changed. The Jest spec then proves the output differs only in font file names. `dist/` is committed and CI verifies it matches a fresh build, so the spec always runs against current output. Injecting a one-property difference or removing a single suffix made the spec fail.
- **Setting order is enforced.** `@use ... with (...)` must be the first load of `fontUtils`, so the template configures it before any font module loads it.
- **Two outputs serve two kinds of consumer.** The ticket asked whether to ship separate stylesheets or a Sass setting. The answer was both, and they share one mechanism: CDN consumers swap a file name, and Sass consumers set `$font-env`.

## Outcome

- All four brand themes now have test and QA stylesheets, in normal and minified form. Switching environment only means adding `-test` or `-qa` after the theme name in the stylesheet file name.
- Test and QA can trial a new font version from permanent addresses without affecting what guests see.
- Every pull request automatically confirms the test and QA stylesheets match production apart from the font files.
- The change is backward compatible; production output is unchanged.
- **Before anyone switches:** the `-test` and `-qa` copies of every font file (English, Japanese and Korean) must be uploaded to `resource.alaskaair.net`. Without them, those pages fall back to system fonts.

## Ticket Completeness

All 6 of 6 acceptance criteria are resolved. Two items the ticket raised outside the checklist are still open.

**Resolved**
- **The `font-face` mixin accepts a `test`/`qa` option that suffixes the file name, with today's URL as the default.** Done through `$env` and `font-env-suffix()`, and extended to `font-face-i18n`.
- **Every theme gets test and QA versions of `*.global.css` and `*.global.min.css`, with production unchanged.** These are the 16 `<theme>-<env>.global(.min).css` files; no production file changed.
- **A post-build test compares production, test and QA output (expanded and minified) and fails on anything but the font URL.** That's `themeFontEnvironments.spec.js`.
- **The test runs in `npm test` and CI and fails the build.** It runs under `jest` in `npm test`, which the CI Test job executes.
- **Sass True tests cover the default, `test` and `qa` output.** That's `fontFace.spec.scss`, which covers both mixins.
- **README and the migration notes explain the naming and usage.** Both are updated.

**Not Resolved / Partial**

## Learnings

- **The ticket's naming example decided the mixin, but not the output layout.** The design changed twice in review (folders, then flat names). Settle the output layout with consumers before building, ideally in a TRD.
- **Broad `.gitignore` patterns can silently drop generated output.** A bare `test` pattern from 2019 ignored a new `dist/bundled/themes/test/` folder, and CI's committed-output check couldn't see the missing files because git ignored them too. When adding new output paths, run `git check-ignore`.
- **Prove a drift check by mutating its input.** Changing one property in a built file and removing one suffix confirmed the Jest spec fails as intended. A comparison that only ever passes proves nothing.
- **Normalize precisely, then also check the opposite direction.** Removing suffixes alone would pass a test/QA file that has no suffixes at all, which is why the spec also asserts every URL is suffixed.
- **Sass load order matters with `@use ... with`.** `_fontFaceI18n.scss` now loads `fontUtils`, so a consumer who loads `fontFaceI18n` *before* configuring `fontUtils` with `with (...)` gets a "module already loaded" error. Configure `fontUtils` first.
- **Avoid the global Sass `if()` function.** It's deprecated in current Dart Sass; use `@if`/`@else`.

## Iterations That Didn't Work

- **Environment folders (`themes/test/`, `themes/qa/`) with unchanged file names.** This was the first layout. It hit the `.gitignore` problem above, which was fixed by anchoring the pattern to `/test`. The layout was then replaced with flat `<theme>-<env>.global.css` file names to match the font naming convention, and the `.gitignore` change was reverted.
- **Suffixing only the English brand fonts.** This followed the ticket's scope note, but a test page then loaded test English fonts with production Japanese/Korean fonts. Both mixins now share `font-env-suffix()`.
