# AB#1683083

## Executive Summary

Teams need to try a new brand font in test and QA before guests see it. Until now every environment loaded fonts from one address, so a new font could only be tried by publishing it everywhere. A first fix (v12.1.0) did this by renaming font files with `-test` and `-qa` endings. After review, that was replaced with a simpler approach: new fonts go into a test/QA folder first, and a separate staging address (`test.alaskaair.com`) serves them with the same file names and paths as production. Each brand theme now has a staging stylesheet that differs from production only in that address. Production is unchanged.

Tracking ticket: [AB#1683083](https://itsals.visualstudio.com/E_Retain_Content/_workitems/edit/1683083).

## Technical Research Document

[Discussion #305: Plan: Test font changes via separate Fastly staging/prod maps](https://github.com/AlaskaAirlines/WebCoreStyleSheets/discussions/305). It proposes splitting the Fastly map into staging and production maps with identical file names and paths, and replacing the #303 suffix approach.

## The Problem

A new brand font could not be tried anywhere without being live everywhere. The v12.1.0 workaround required every font to be uploaded a second time under a different name, added special options to the code, and shipped sixteen extra stylesheets that nobody used.

## Root Cause

Font URLs had one host and no notion of environment. The v12.1.0 fix worked around that inside the stylesheet (`$font-env`, `font-env-suffix()`, `$env` on `font-face` and `font-face-i18n`) instead of in routing. Because Fastly can serve a staging host from the test/QA folder, the file-name suffix was redundant.

## The Fix

- Removed `$font-env`, `$font-envs`, `font-env-suffix()` and the `$env` arguments. Default output is byte-identical to before.
- Deleted the 16 `-test`/`-qa` bundles and their specs.
- Added `<theme>-stg.global(.min).css` for Alaska, Alaska Classic, Atmos and Hawaiian. The theme template configures `fontUtils` with `$i18n-font-host` from a `FONT_HOST` placeholder, and the build writes one production and one staging file per theme.
- Added [themeStagingBundles.spec.js](../../tests/themeStagingBundles.spec.js), and `npm run verify:fonts` ([verify-fonts.mjs](../../scripts/verify-fonts.mjs)) to check the live font URLs.
- Updated README, MIGRATION, the SassDoc output and this post-mortem.

## Why This Works

File names and paths are identical across hosts, so promoting a font to production is a copy, and the stylesheet that ships is the one that was tested. The Jest spec fails if a staging bundle differs from production in anything but the host. `verify:fonts` covers what that spec can't see: whether the files exist and are served correctly.

## Outcome

- Every brand theme has a staging stylesheet that loads fonts from `test.alaskaair.com`.
- Production stylesheets and default output are unchanged. `verify:fonts --prod` confirmed all 17 production font URLs return 200 with a font content type and CORS header.
- Staging isn't usable yet: the same check against staging returned 404 for all 17 URLs, because the fonts and the Fastly staging map haven't been set up.

## Ticket Completeness

3 of 6 acceptance criteria resolved in their original form; the others were intentionally replaced by the approach in discussion #305.

**Resolved**
- Production output is unchanged and keeps today's unsuffixed URLs.
- A post-build test runs in `npm test` and CI and fails when a staging bundle differs from production in anything other than the font address.
- README and migration notes explain how to use the staging bundles.

**Not Resolved / Partial**
- **`font-face` environment option (`test`/`qa` suffix):** removed on purpose. Routing by host replaces it.
- **Test and QA versions of each bundle:** partial. There is one staging bundle per theme (`-stg`), not separate test and QA bundles.
- **Sass True tests for the option:** none, because the option no longer exists.
- **Font host coordination (risk in the ticket):** outside this repo and not done. The Fastly staging map and font uploads are still needed.
- **"Breaking change: None":** no longer accurate. This removes API that shipped in 12.1.0. Per the discussion nothing consumed it.

## Learnings

- Environment-specific file naming pushes complexity into every consumer; routing by host keeps the stylesheet simple.
- A text-comparison test can't tell you whether files exist on a server; keep a separate, network-based check out of CI.
- Prove a drift check by mutating its input: change one property in a built file and confirm the spec fails.
- Broad `.gitignore` patterns (a bare `test`) can silently drop generated output; run `git check-ignore` when adding output paths.
- `npm run build` regenerates `docs/` and deletes untracked files there. Commit hand-made pages such as `docs/theme.html`.
- Check the host name against the source of truth: the first version of this change used `test.alaskaair.net` instead of `test.alaskaair.com`.

## Iterations That Didn't Work

- **Suffixed file names per environment (v12.1.0).** It required duplicate uploads, added code options and unused bundles, and was replaced by host routing.
- **Runtime host swap in `docs/theme.html`.** The preview page replaced the production host in the CSS in the browser; it now loads the `-stg` bundle so the preview matches what ships.
